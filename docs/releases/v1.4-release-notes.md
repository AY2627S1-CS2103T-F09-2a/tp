# Poco Book v1.4 — Alpha Release

Poco Book helps independent tutors keep student records, guardian contacts and outstanding fees in one place. Built on AddressBook Level 3 (AB3), it combines typed commands with a graphical interface for viewing records and following up on unpaid fees.

This alpha builds on the v1.3 MVP with guardian-contact editing and search, deletion confirmation, minimum-fee filtering, all-student fee totals and full-payment recording. It also includes in-app command help, clearer summary feedback, fixes to student selection, and documentation and developer-tooling updates.

## What’s new compared with v1.3

### 1. Update guardian contacts without recreating a student

[Insert screenshot 1 here]

Updating a guardian’s phone number while keeping the student’s other details.

Keep a student’s guardian information current when a contact name or phone number changes.

edit INDEX [g/GUARDIAN_NAME] [gp/GUARDIAN_PHONE]

To change guardian details, supply either guardian field or both. These fields can also be combined with other supported edit fields. For example:

edit 1 g/Mei Tan gp/92345678

edit 1 gp/98765432

- INDEX identifies the student in the currently displayed list, including filtered results.

- Change the guardian name, phone number, or both. Fields you omit keep their existing values.

- Untouched student contact fields, guardian fields, tags and outstanding fees are preserved. Successful changes use the normal automatic-save path.

- Blank, invalid or repeated guardian prefixes are rejected. A change that would duplicate another student’s identity is rejected without changing the record.

A successful edit returns to the full student list, following the existing edit behaviour. Guardian fields cannot be cleared, and f/ remains unsupported by edit; use setoutstanding to change the amount owed.

### 2. Find students using a guardian’s name or phone

[Insert screenshot 2 here]

Finding students by guardian name or phone.

Locate the relevant student records when a guardian contacts you and you remember the guardian’s details rather than the student’s name.

findguardian KEYWORD [MORE_KEYWORDS]...

Examples:

findguardian Mei

findguardian 92345678

- Matches whole guardian-name words without regard to case, or an exact eight-digit guardian phone number.

- Multiple keywords use OR matching: a record appears when any keyword matches.

- Searches all stored students, even when another filter is active. Matching records retain their stored order and receive displayed indexes starting from 1.

- Partial name words and partial phone numbers do not match. A guardian shared by several students can return several records; check the student name before acting on an index.

- The result shows N student(s) listed! Zero matches is a successful empty result. Missing or malformed keywords and prefix-style input are rejected.

- Searching does not change student data. Run list to return to all students.

The existing find command continues to search student names.

### 3. Confirm a student before deleting their record

[Insert screenshot 3a here]

Confirming deletion with the student and guardian details visible.

[Insert screenshot 3b here]

Warning that deleting a student also removes their unpaid fee.

A confirmation step helps prevent accidental deletion when working through a student list or filtered results.

delete INDEX

- For a valid displayed index, the dialog shows the student’s name, student phone (or Not provided), guardian name and guardian phone. It also states that deleted students cannot be restored.

- Press Y or click Delete (Y) to delete the student. Press N or Escape, close the dialog, or click Cancel (N) to keep the record. Cancellation reports: Deletion cancelled. No student was deleted.

- Enter, Space and Tab do not confirm deletion, and the buttons cannot be reached using the keyboard. Y/N with Control, Command or Alt is ignored; Shift is allowed. Use Y or N as the dialog’s keyboard response.

- Invalid command input is rejected before confirmation.

- If the student owes fees, a prominent warning displays the outstanding amount and explains that deleting the student also deletes the unpaid fee. Deletion is still allowed after confirmation.

Check the identity shown before responding. The target is checked again before deletion; if the displayed student has changed, nothing is deleted. Confirmed deletion follows the existing save and re-indexing path and removes the complete record, including guardian and fee information.

### 4. Prioritise students who owe at least a chosen amount

[Insert screenshot 4 here]

Filtering students with fees min/100.

Narrow the outstanding-fee list when you want to follow up on larger balances first.

fees min/AMOUNT

For example:

fees min/100

- Shows students owing at least S$100.00, including students owing exactly S$100.00.

- Accepts a threshold from 0 to 99999.99, with at most two decimal places. Signs and scientific notation are not accepted.

- fees min/0 still shows only students with a positive outstanding fee. Students without a fee remain excluded.

- Results retain stored order and are re-indexed from 1. A zero-match result is allowed.

- Blank or malformed amounts, repeated min/ prefixes, unknown prefixes and extra arguments are rejected without changing data, the filter or selection.

- Plain fees keeps its existing behaviour. Run list to restore all students.

This is a filter, not an amount-based sort. Clearing a displayed student’s fee removes that student from the outstanding-fee results.

### 5. Review the total outstanding across all students

[Insert screenshot 5 here]

Showing the all-student fee total while a search filter remains active.

Get an overall fee balance without leaving the records you are currently reviewing.

feesummary

- Reports the number of students with outstanding fees and their combined amount across all stored students.

- The summary covers the entire student book, even when the displayed list is filtered by a name, guardian or minimum fee.

- Amounts use exact decimal arithmetic and display two decimal places. The combined total can exceed the maximum fee for one student.

- Preserves the current filter, selection and saved data. Extra arguments are rejected.

For two students owing S$180.00 and S$75.50, the feedback is:

Across all stored students: 2 student(s) owe a total of S$255.50. Displayed list unchanged.

When no students owe fees:

Across all stored students: 0 student(s) owe a total of S$0.00. Displayed list unchanged.

### 6. Mark a student’s full outstanding fee as paid

[Insert screenshot 6a here]

Outstanding-fee list before recording a full payment.

[Insert screenshot 6b here]

Paid confirmation and the refreshed outstanding-fee list.

Clear the recorded balance after receiving full payment, with feedback showing the amount removed.

paid INDEX

For example, run fees, check the student currently shown at index 1, then enter:

paid 1

- Removes that student’s entire outstanding fee while preserving other student and guardian details.

- Uses the currently displayed index and preserves the active filter.

- In an outstanding-fee result, the paid student disappears and the remaining records are re-indexed. In a name search, the student remains visible if they still match.

- A student without an outstanding fee is rejected. Missing, malformed or out-of-range indexes leave data and the displayed list unchanged.

- The change is saved automatically through the normal save path. If saving fails, the in-memory change may remain; persistence after restart is not confirmed.

For Riya Kumar owing S$75.50, the feedback is:

Marked outstanding fee as paid for Riya Kumar: S$75.50

setoutstanding INDEX 0 remains available. paid records your decision that a fee has been paid; it does not process or verify a bank transaction.

### 7. Read command help without leaving the app

[Insert screenshot 7 here]

Reading help paid in the result area.

Look up syntax and constraints directly in the result area, alongside your current student list.

help COMMAND

Examples:

help paid

help setoutstanding

- Shows the requested command’s purpose, syntax, example and relevant constraints without executing it. For example, help paid explains payment recording without clearing a fee.

- Preserves the displayed list, selection and student data, and does not write to storage.

- Plain help keeps the existing help window and online-guide link.

- Unknown command words, incorrect capitalisation and extra arguments such as help paid 1 return usage guidance and an alphabetical list of available commands.

- Long help text wraps in the result area; scroll vertically to read the remaining lines.

Command-specific help covers all 14 registered commands, including help findguardian. Help is read-only and does not execute the command being described.

### 8. Keep the details pane on the correct student

[Insert screenshot 8 here]

Keeping the same student selected after changing the search results.

The selection fix prevents a search from moving the highlight and details pane to a different student merely because the new results have the same number of rows.

- If the previously viewed student remains in the new search results, that same student stays selected at their new displayed index.

- If the student is absent from the new results, the selection and details pane clear.

- Editing a selected record, changing its fee or recording payment tracks the updated student while they remain displayed.

- If saving fails after an in-memory change, the selection is corrected to the relevant displayed student or cleared. A rejected command that leaves the selection unchanged does not cause an unnecessary scroll.

For example, find Alex Bernice → view 2 → find Bernice David keeps Bernice selected at index 1. It no longer switches the pane to David. A save failure is still reported and does not guarantee persistence.

### 9. Updated guides and developer support

- The merged User Guide and Developer Guide now cover feesummary and paid, including examples, command-summary entries, use cases and manual-testing steps. The Developer Guide includes the payment sequence diagram and an updated model diagram for guardian fields and optional contacts/fees.

- The guides also cover guardian editing and search, minimum-fee filtering, deletion confirmation, command help, clearer fee-summary feedback and selection behaviour. The Developer Guide includes the minimum-fee filtering sequence diagram.

- Java assertions are enabled for Gradle application runs. The setup guide explains the -ea option for direct IntelliJ runs; a direct JAR launch needs java -ea -jar addressbook.jar to enable assertions.

## Download and run

Use the v1.4 addressbook.jar after the release is published. The release candidate requires Java 25. The JAR built on macOS includes both Intel and Apple Silicon Mac libraries, alongside the existing Windows and Linux libraries.

- Install the prescribed Java 25 runtime.

- Download the verified v1.4 addressbook.jar from the release’s Assets section.

- Place the JAR in a dedicated folder. Back up existing data before replacing an older JAR.

- Open a terminal in that folder and run:

java -jar addressbook.jar

Start with list to see the available students. Use help for the online-guide window, or help COMMAND for in-app instructions. Use indexes from the list currently on screen; they can change after filtering, payment or deletion.

## Compatibility and existing data

The v1.4 changes retain the v1.3 student model and JSON format; no schema migration is introduced. Back up your v1.3 data before upgrading. Automated integration tests cover guardian search, displayed-index payment, saved-data preservation and persistence after reload.

Data remains in data/addressbook.json under the application’s home folder. Keep a backup before upgrading or manually editing the file. Older AB3 records without the required guardian fields are not automatically migrated.

If data cannot be loaded, the existing recovery behaviour starts with an empty record list. A subsequent successful record-changing command can overwrite the data file with that new state. Restore or protect your backup before entering changes.

## Known limitations

- Each student has one guardian contact.

- Fees represent the current outstanding amount. Invoices, receipts, payment history and partial-payment transactions are outside this release’s selected scope.

- paid clears the full amount. setoutstanding replaces the recorded amount; it does not subtract a payment.

- Phone numbers remain restricted to the supported Singapore format; international-number support is not part of the selected v1.4 scope.

- The minimum-fee filter preserves stored order and does not sort balances. feesummary always totals all stored students; it does not total only the visible subset.

- Deletion confirmation has no undo. While the dialog is open, a Y or N typed as part of another command can still answer it; respond to the dialog before typing another command.

- Teaching groups, lesson tracking, multiple guardians, reminders and export remain deferred.
